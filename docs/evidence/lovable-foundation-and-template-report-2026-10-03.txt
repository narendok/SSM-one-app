Readable lifecycle data

All five tables use authenticated, RLS-scoped reads only:

department_process_templates
id, department_id → departments, template_key, version, title, description, status (DRAFT | ACTIVE | RETIRED), provenance/timestamps.
Read predicate: current user can access that department Drive.

department_process_template_stages
id, template_id → templates, stage fields, source_company_process_stage_id → company_process_stages, task_department enum, required/provenance fields.
Read predicate: parent template is visible.

project_stage_dependencies
Directed stage-to-predecessor links, both FKs point to project_process_stage_records.
Read predicate: current user can access the linked project/department.

project_feedback_revisions
Project, active requirement baseline, revision/status (DRAFT | SUBMITTED | ACCEPTED | SUPERSEDED), optional same-project Drive source, provenance/timestamps.
Read predicate: current user can access the project; baseline and optional Drive source must match the project scope.

project_lifecycle_generation_requests
Request key, project/template/version, requesting actor, payload hash, persisted result and timestamp.
Read predicate: only the actor who requested it.

Related provenance fields are available on project stage records and tasks. Drive revisions use sha256_checksum, not checksum.
